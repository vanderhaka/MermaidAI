# S3 Main Run: Tool-Backed Resolved-State Truth Contract

## Scope

Prevent selected open-question drawer clicks from being treated as answers or resolved state.

- `src/app/api/chat/route.ts`
- `src/app/api/chat/route.test.ts`

- `src/lib/services/prompt-builder.test.ts`
- `src/lib/services/llm-tools.ts`
- `src/lib/services/llm-tools-scoping.test.ts`

## Implementation Notes

- Added structured `context.resolvingOpenQuestion` validation to the chat API request.
- Passed selected-question identity into prompt context and the tool executor.
- Added a tool-executor guard that blocks `resolve_open_question` when the latest user message is only the drawer's resolve prompt.
- Added prompt instructions making live `Current Open Questions` the source of truth.
- Added deterministic API handling for click-only selected-question requests when the DB still lists the question as open. This returns the exact question plus a recommended answer without calling the model, preventing stale chat history from claiming "Already resolved."
